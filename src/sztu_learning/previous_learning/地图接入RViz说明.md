# 最终导航地图怎样进入RViz

**2026-11-20后续进展：** 本文下方保留的是此前目标说明。
现已生成maps/lesson57_rviz_map候选地图，并经真实map_server和RViz加载显示，
固定坐标系使用learning_map，尚未验收自主导航或整机通行。
运行方式、截图及验收范围见地图生成与RViz验收.md。

本文件说明目标接入方式，不表示当前地图已生成或已加载。
本机已安装Humble的nav2_map_server 1.1.20、nav2_lifecycle_manager 1.1.20和rviz2 11.2.29；
本轮只读取安装信息，没有启动地图服务或RViz。

```text
逐帧点云、同源位姿与传感器信息
  → 构建占据/空闲/未知栅格
  → 导出地图图片.pgm + 地图参数.yaml
  → map_server读取并启用
  → /map话题（nav_msgs/msg/OccupancyGrid）
      ├─ RViz的Map显示项：画地图
      └─ 导航/定位组件：使用地图
```

PGM图片保存格子的图像编码；YAML说明图片路径、每像素多少米（resolution）、
图片左下角在地图参考系中的位姿（origin）及占据/空闲阈值、编码方式等。
这里的origin不是机器人起点，也不自动是坐标(0,0)。导出时必须处理数组行方向和图片上下方向。
占据/空闲/未知的ROS消息表示通常采用100/0/-1；PGM的像素灰度另有编码规则，不能直接照抄数值。

map_server是ROS 2节点，负责读取文件并发布/map，不负责计算建图、定位或控制机器人。
它是生命周期节点，需要配置并激活，后续会用启动文件自动完成，避免每次手动输入多条命令。
地图消息携带格子状态、宽高、分辨率、覆盖区原点及header.frame_id。
最终统一约定地图参考系后，在RViz把Fixed Frame设为对应frame（通常命名map），
添加Map显示项，Topic选择/map；QoS采用Reliable与Transient Local接收保留的静态地图。
静态图不必不断重发，较晚启动的RViz也可从保留消息读取它。
RViz标准Map显示项主要订阅地图话题，不是直接把PCD或PGM拖进窗口就成为可导航地图。

只有地图显示时，Fixed Frame等于地图消息参考系即可，不要求已经连上机器人或有完整TF树。
还要在地图上显示机器人的位置和朝向时，需要定位系统提供一致的坐标变换，
常见关系map→odom→base_link；实际接口参考点/外参必须正确，不能凭名称伪造位置。
地图与机器人同框显示不代表定位正确，RViz里的箭头也不是导航已经成功的证明。

RViz负责显示及提供交互工具；真正执行导航的是后续接入的导航节点、控制适配和机器人底层。
可用RViz的目标点工具发出目标，但必须先接通实际接收该目标的导航组件才能产生运动。
我们后续使用自己的开源ROS链路，不启动未采购的厂商导航编排。

运行位置计划：先在电脑离线用domain42、仅本机发布地图并查看；
真机阶段地图/定位/导航与电脑RViz的通信按当次实际架构与ROS域配置接通，不能沿用仅本机隔离设置。
最终地图文件、同源位姿/点位、坐标变换和运行来源一起保存，避免跨FAST-LIO运行混用。

当前只有点云、轨迹、候选切片和点落入网格，未产生可靠自由空间的导航地图。
正在继续逐帧保存，以便后续恢复观测起点、处理合理高度并构建栅格；不为了在RViz显示而把未知格改空闲。
