# 连续定位：独立移动录包回放版

2026-11-20。完成范围是电脑上的连续地图定位原型：使用另一趟遥控行走数据，
在先前保存的固定地图中，连续更新胸部 IMU 原点的地面投影位置和朝向，
再用同时间戳的动态TF换算机器人base_link地面投影和正前方。
这次没有部署机器人在线定位，也没有下发运动指令。

  墙面来自上述地图同一次建图的三维点云；保留高度，补足二维栅格丢失的表面细节。

- 新 FAST-LIO 档案：`maps/localization_20261120_run02`，1517组成对输出。
  新运行的重力与地板参考由其自身初始数据估计，没有套用旧地图的坐标变换。

  参考上一次静止定位和用户仍在场地内的信息；只是搜索提示，不是真值。

`maps/localization_20261120_run01`明确作废，原因保存在

## 核心程序各做什么

```text
新雷达 + IMU → FAST-LIO → 连续里程计 + 配准点云
                               ↓
                    本次重力/地板参考、保留点高度
                               ↓
             连续里程计预测位置 + 固定三维地图周期校正
                               ↓
                 当前位姿、当前点云、轨迹、有效状态
```

`continuous_localizer.py`管理连续状态。里程计每来一帧就预测当前位置；
地图匹配周期约0.5秒。最近0.8秒的观测先按里程计对齐，避免运动时直接叠加点云。
注册点云已经在FAST-LIO世界系中，不再乘一次机体位姿。

`spatial_localizer.py`保留XYZ做对应搜索，只求地图平面的x、y、yaw。
先在较宽范围初始化，随后围绕里程计预测位置搜索±0.20m、±6°。
细化阶段使用最多500点求解，最终质量判定使用最多1200点；保持端点代价下降。
三维点对应帮助区分不同高度物体；表面法向继续用于判断位置和朝向是否有足够约束。

几何判据使用真正匹配表面的雅可比：XY共同缩放、yaw按其实际响应缩放，
再检查归一化信息矩阵最小/最大特征值比是否至少0.02。
这避免用未参与匹配的全部扫描点距离来决定几何尺度。
测试验证坐标旋转与角度参数尺度变化不影响此判据，单墙缺失方向仍被拒绝。
这不是定位协方差或实测精度。

`continuous_localization_node.py`将它接成ROS节点，后台线程计算地图匹配，
接收线程继续处理里程计。只保留有限配对缓存、最多一个匹配任务，没有无限待处理队列。
`replay_localization_archive.py`按原始消息时间戳和`/clock`以1倍速回放。

## 什么情况下失效

- 输入时间倒退或重复：不更新旧数据；异常输入、跳变或断流：不继续输出有效位姿。
- 消息年龄超过0.4秒，或接收墙钟超过0.6秒没有新配对输入：定位丢失。
- 匹配结果超过0.8秒：不采用。首次初始化最多等待5秒。
- 短暂匹配失败：最多沿里程计预测2秒，状态明确为降级；超时后丢失。
- 地图校正超过0.25m或10°：拒绝。丢失后锁定，需要核实初值并重新初始化。
- 位姿停止发布、当前箭头删除、TF不再刷新；历史轨迹保留供查看。

输入跳变筛查上限为胸部IMU平面速度2.5m/s、角速度3.5rad/s，
不是机器人运动限速。参考旧移动记录最大约1.69m/s、2.28rad/s并留余量；
胸部摆动和腰部转动不能当作底盘速度。这些是原型筛查参数，不是硬件安全阈值。

## 验收证据

22项相关测试通过：已知位姿恢复、带噪声/异常点、单墙退化、重复结构、错误区域、
错误高度、转弯预测、断流、迟到结果、异常校正、运动窗口与几何尺度等。
另验证机体杆臂、腰部旋转及三维安装方向转换。执行入口为仓库`tools/run_tests.sh`，没有运行无关包测试。

独立新录包的批量回放1517/1517帧保持有效，266/266次地图校正通过。
地图匹配耗时中位数约0.041秒、p95约0.050秒；它不是整机端到端延迟。
实际ROS以1倍速回放的结果保存在`runtime_logs/continuous_robot_base_ros_20261120`。
总验收、源码快照和路线图保存在`runtime_logs/continuous_acceptance_robot_base_20261120`。
以其中保存的状态、最后输入时间、输出间隔、断流和显示核对为依据。

实际ROS全段输出1513条位姿，初始化后接到最后一帧；输出间隔中位数约0.100秒，
p95约0.101秒，最大消息时间间隔约0.106秒。输入结束后墙钟超时进入丢失状态，停止位姿输出。

过程中的二维匹配、三维细化、几何尺度和初始化超时失败均保留日志，
不使用“同包走通”代替独立运行验证；本轮新录包也是调试数据，不是未使用过的盲测数据。

## 怎么查看

在电脑的ROS终端运行：

```bash
bash src/sztu_learning/view_continuous_localization.bash
```

只运行在电脑`ROS_DOMAIN_ID=42,ROS_LOCALHOST_ONLY=1`。
白/黑/灰是原固定地图，绿色是本次回放的机器人中心投影轨迹，橙色箭头是当前回放机器人正前方，
青色是当前扫描点的平面显示；Z=0.04只是显示高度。
录制开始有一段静止等待，约后半段才开始明显行走；回放结束会清除当前箭头。
这不是机器人此刻的实时位置。关闭RViz会结束这一组显示进程。

IMU话题：`/learning/localization/imu_pose`；机器人投影话题：`/learning/localization/robot_base_pose`。
有效性必须同时看`/learning/localization/status`。
专用TF：`learning_map → learning_tracked_imu_planar`及`learning_map → learning_robot_base_planar`。
没有发布真实机体TF树里的`map → base_link`或`/slam/lidar_odom`，没有接导航控制口。

## 箭头朝向修正

学习者指出最初箭头朝向不对。原先箭头使用IMU的+Y轴，用户会自然把它理解为机器人前方，
该显示语义不合适。现由robot_base_projection.py从本趟原始包提取逐帧base_link到IMU的完整动态TF，
在FAST-LIO输出的同一时间戳查找、插值，完整处理安装旋转、杆臂和腰部运动。
1517帧都有精确时间查询结果，不使用最新TF兜底；数据在runtime_logs/continuous_base_tf_20261120。

这趟IMU+Y相对机体+X的夹角约75.34°～100.22°，并非常量。
新的箭头和绿色轨迹采用机器人base_link地面投影，前方取base_link的+X。
实时消息的箭头/机体位姿/同时间戳运动学数值核对见runtime_logs/robot_heading_acceptance_20261120。
该核对证明计算和消息一致；没有用现场仪器测量机体绝对朝向。

## 还差什么

接入真机实时数据和本次启动参考初始化，把已实现的机体转换接到在线动态TF；
现场验证腰部转动、实时延迟、丢失后重新初始化与新的独立路线。
FAST-LIO的点时间ns解释、名义外参和运动补偿限制仍保留，尚无独立位置/朝向真值。
地图匹配残差不能当作机器人绝对定位误差。
自主行走还需要运动控制链、机器人净空和实时避障，不能因本次回放通过就直接下发导航。

本轮复用学习目录既有的FAST-LIO、点云适配、配对档案和静止匹配基础；
原项目只参考了“FAST-LIO body是IMU、base_link需要动态转换”的处理思路，
没有调用未采购的厂商SLAM/导航模块。
