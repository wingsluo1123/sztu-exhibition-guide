## 程序与判据

planar_localizer.py为可独立测试的功能模块，使用NumPy、SciPy、Pillow与PyYAML。
从PGM/YAML读取三态地图，未知不作为障碍匹配目标；在初值的x/y各±0.6m、yaw±20°内粗搜索，
再对地图局部线面对应作稳健迭代。不是直接调用厂商或原项目的定位算法。

候选判据是本次原型工程选择，尚非导航置信度或精度保证：

- 至少80个去重观测点；最多1200个点参与匹配，XY体素8cm。
- 至少55%的端点距占据格中心小于15cm（3个栅格），对应端点RMSE不超过8cm。
- 有效局部表面对应点至少80个，最终对应也限定15cm，平面残差RMSE不超过8cm。
- 归一化位置/朝向约束矩阵的最小/最大特征值比至少0.02，防止单墙沿墙方向没有约束。
- 搜索得到的明显不同候选若代价近似相同则拒绝；只检查本次有限搜索范围和起始候选，不保证全局唯一。
- 观测原点须落在已知自由格。拒绝时pose_xy_yaw为空，不发布可用位姿。

地图包含桌椅等非平面投影，不能要求所有端点都有可靠直墙法向。
因此“全部端点与占据格的一致性”和“足够的有效表面及几何约束”分别检查。
首版将25cm搜索候选也计入最终误差；第二次又要求55%的所有端点都有线面法向。
两次拒绝结果及源码保存在attempt01/attempt02。最终修正统计语义，未上调8cm误差上限，
并增加非平面物体与无几何约束实心块控制，检查修改没有让无约束输入获得位置。

## 后续教学起点

先讲localize_scan.py中的三行功能关系：

```python
points = data[scan_key]
matcher = PlanarLocalizer.from_directory(map_directory)
result = matcher.match(points, seed)
```

第一行从新采集的NPZ中取二维实测端点；第二行读取固定地图并建立匹配器；
第三行才执行匹配，seed是大致x/y/朝向，result包含是否通过和位置。
不先要求理解优化器内部的全部矩阵计算；以后围绕实际功能逐段解释。
