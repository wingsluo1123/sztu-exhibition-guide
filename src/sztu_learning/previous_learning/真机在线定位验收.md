## 计算与显示分别在哪

```text
机器人：实际雷达 + 实际IMU
          ↓ online_sensor_adapter.py 保留时间戳、转换逐点格式
        学习副本 FAST-LIO
          ↓ /learning/online/odometry + /learning/online/cloud_registered
        当前启动重力/地板参考 + 固定地图匹配 + 同时间机体TF
          ↓ 机器人base_link原点地面投影、前方朝向、定位状态
        online_display_bridge.py --robot-stream
          ↓ SSH，只传显示数据；不包含控制入口
电脑：  online_display_bridge.py（本机domain42）
          ↓ 位姿、路径、点云、当前箭头
        固定map_server + RViz
```

机器人使用厂商DDS环境和domain0、真实时间；电脑显示使用domain42和本机通信。
没有把机器人原始点云通过电脑DDS重新发布回真机。
FAST-LIO自己的TF改到私有学习话题，不向真实机体TF树加入 `camera_init→body`。
当前箭头来自 `base_link +X`，包含动态腰部变换；不是统一给IMU箭头加减90°。

电脑显示桥还修正了跨电脑时钟偏移符号，保留延迟及不确定度检查。

## 运行方法

以下启动的是定位及显示，不会使机器人运动。启动时机器人应停稳，并提供大致起点与朝向。

机器人终端：

```bash
bash ~/sztu_learning/live_release01/run_online_robot.bash \
  --run ~/sztu_learning/online_runs/new_unique_name \
  --duration 180 --seed 0.3 -0.2 -22.3
```

`--seed` 是地图中的IMU地面投影大致X/Y和IMU+Y朝向（度），不是base_link朝向。
示例数值仅适用于本次原起点、原朝向；换方向或起点须重新给初值。
程序拒绝覆盖旧目录；时间到或Ctrl+C结束；需要留原始传感器可额外加 `--record`。
启动脚本要求 `sztu-bridge` 已停止，不会自行启动导航服务，也不创建开机自启。

电脑终端：

```bash
bash src/sztu_learning/view_online_localization.bash
```

`view_continuous_localization.bash` 仍是旧录包回放入口，不能同时启动。
电脑SSH需能免密连接 `agi@192.168.224.19`。
电脑与机器人断开、数据过期或机器人报告定位失效时，删除当前箭头；历史线不代表当前位置。
当前电脑显示桥是单向的，没有连接RViz的初始位姿工具。
机器人内部预留 `/learning/online/initialpose` 手动重初始化入口，尚未做现场操作验收。

## 代码来源与边界

在线节点由学习目录已有的、先前验证过的定位代码扩展而来。
FAST-LIO来自本学习目录保存的开源学习副本，已在机器人ARM环境重新编译。
使用真机TF核对候选外参，没有调用原项目导航控制，也没有使用厂商未采购SLAM/导航模块。

这是需要大致初值的小场地在线定位原型，不是全局重定位，不包含回环、避障或自主导航。
逐点时间仍采用此前验证的“相对纳秒”候选解释，外参采用名义安装值；不声称完成物理标定。
换场地、快速行走、遮挡或重启后的可靠性仍需要另外验证。
