## 当前配置与范围

- 首次接入只验证已知静态地图、现场清空且持遥控器监督的短路线。当前成本地图只有StaticLayer和InflationLayer，**未接实时障碍物输入，不具备动态避障验收**。
- 暂用半径0.40m；直线指令上限0.15m/s，旋转上限0.70rad/s；不发侧移或倒退。超过边界拒绝并停车，不将小速度擅自抬高。
- 位置容差0.15m，朝向容差0.10rad。本地候选使用官方SimpleGoalChecker且stateful=false，使结束时位置和朝向同时达标。行为树只规划一次、跟踪一次，无自动重试、Spin或BackUp恢复。转向时位置变化和停车尾随仍需闭环实测。
- 转向请求候选为0.20rad/s，请求角加速度0.50rad/s²；末端1m内由RPP降低前进请求，最低0.05m/s。这些值尚未实测步态起步/低速响应，不是已验证物理参数。
- 没有整趟30秒期限。Nav2另有15秒无位置或朝向进展检查，控制层保留0.20秒心跳/指令超时、定位有效性/新鲜度、MC状态和地图净空检查。实走累计距离由--max-distance指定，默认仍为原试验的2m；仅规划不受此物理距离上限限制。官方动作成功后发零并等待2.5秒，再核对位置和朝向；现场停稳仍需操作人确认。
- 未知区域参与膨胀，规划footprint_padding为sqrt(2)×0.05m，用于栅格离散余量；试验身体半径仍为0.40m。靠边目标可能因规划净空不足而拒绝。路线和精确点击终点还须通过已有GridRoute的已知净空检查。
- 控制器软件会输出低于峰值的小旋转或弧线指令。是否足以驱动本机、脚步尾随是否破坏最终容差，必须用新真机试验验证。软件模型通过不等于实机已通过。
- 转向候选将RPP的max_angular_accel从1改为28rad/s²。这是速度请求适配参数，不是实测的机器人加速度：控制频率20Hz，单周期允许改变量1.4rad/s，使测得转速在±0.70rad/s内时仍能请求正确方向的±0.70。真实输出门禁仍为±0.70，未反转SDK符号、未给所有小指令加最小速度。理由、复现与尚未解释的反向起步见验证记录。

## 运行位置

机器人运行定位、Nav2和厂商接口：

```bash
bash nav2_integration/run_robot.bash bringup --output /absolute/run/path --seed X Y IMU_YAW_DEG
```

此命令只启动定位与Nav2，不创建运动控制器。先以诊断模式检查一条目标路线：

```bash
bash nav2_integration/run_robot.bash mission --relative-goal 0.6 -0.4 --output /absolute/diagnostic/path
```

诊断模式会短暂请求Nav2任务、记录原始Twist后取消，不注册MC输入源、不发送厂商速度。新增--plan-only只计算和显示路线，连NavigateToPose也不请求。真正实走需要另加--execute-one-attempt，并按该次现场授权执行一次。RViz目标模式使用--rviz-goal，默认接收地图内任意可达位置和所选终点朝向。旧测试区域仅在显式--approved-relative-goal 0.6 -0.4时启用。

电脑运行显示界面：

```bash
bash nav2_integration/view.bash
```

电脑domain42/localhost，机器人domain0。SSH中继沿用已验证的一次目标机制，支持查看Nav2规划路径和用户目标；不让PC直接连接机器人DDS运动接口。
