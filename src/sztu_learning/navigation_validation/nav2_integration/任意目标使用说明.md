# RViz 地图内自由选点

当前候选为nav2_release08，代码在学习目录navigation_validation/nav2_integration。规划使用官方Navfn A*，转向与跟踪使用官方RotationShim + RegulatedPurePursuit，没有另写导航控制算法。转向请求候选0.20rad/s，末端最低前进请求0.05m/s；实际步态能否执行这些低速请求尚需现场验证。

## 现在可以选择什么

RViz默认允许点击整张已保存地图，不再限制为“前方0.6米、右侧0.4米”附近。按下“2D Goal Pose”，在目标位置按住鼠标，再拖出终点朝向后松开。

点到障碍物、未知区、地图外或身体净空不足的位置，电脑端会提示并继续等待重新选择。通过本地检查后，机器人端使用同源地图再次检查，并请求Nav2规划；不连通或规划失败的目标会结束本次任务，不发送运动指令。规划成功后还检查整条路线、起点接入和精确点击终点的连接，防止Navfn容差返回附近终点时漏检最后一段。

身体暂用现场已接受的0.40米半径；Nav2另加约0.071米栅格离散余量，并将未知区边缘纳入膨胀。这是保守规划余量，可能拒绝部分靠边目标，不代表可以贴墙走。没有接入实时障碍物输入，仍用于现场清空的静态路线。

## 电脑与机器人各运行什么

机器人负责现有FAST-LIO定位、Nav2及AimDK接口。先启动无运动输出的bringup（起点seed必须符合当前现场）：

```bash
bash /home/agi/sztu_learning/navigation_validation/nav2_release08/nav2_integration/run_robot.bash bringup \
  --output /home/agi/sztu_learning/navigation_validation/runs/free_goal_localization_01 \
  --seed X Y IMU_YAW_DEG
```

这里X、Y、IMU_YAW_DEG需要使用当前已确认的定位初值，不能将这三个占位符直接运行。实走前检查sztu-bridge已停止，且没有另一套运动任务。

电脑启动地图和RViz，并通过SSH传递目标、位姿和路线：

```bash
bash /home/sztu/sztu/src/sztu_learning/navigation_validation/nav2_integration/view.bash
```

仅预览任意目标的路线：在机器人另一个终端运行，看到等待目标后再点RViz：

```bash
bash /home/agi/sztu_learning/navigation_validation/nav2_release08/nav2_integration/run_robot.bash mission \
  --rviz-goal --plan-only \
  --output /home/agi/sztu_learning/navigation_validation/runs/free_goal_plan_01
```

此模式只调用ComputePathToPose，显示蓝色路线和目标箭头，不调用NavigateToPose，不注册运动源，不向AimDK发送速度。

实走使用同一入口，将--plan-only换为--execute-one-attempt。--max-distance M控制单次允许累计行走的米数，须按本次现场范围决定。默认2m沿用之前的试验边界；它与“可以点击地图哪里”是两个独立设置。仅规划不会受到2m限制，实走路线长度或累计距离超过所设上限则拒绝/停车。没有整趟任务时间上限，保留定位/通信异常和无进展检查。

本版本每次任务只接收一个目标。成功传递一次后不要再点第二个目标；下一趟重新启动mission和view，输出目录也换一个新名字。这样不会在恢复连接后重放旧目标。

需要复现原短距离测试入口时，电脑可用view.bash restrict_trial_goal:=true，机器人mission同时加--approved-relative-goal 0.6 -0.4；默认均不启用。
