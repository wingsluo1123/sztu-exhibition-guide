# 按到点结束的本地候选（2026-11-21）

用户要求：“不应该有这个时间限制，应该是等到动作完成后才执行停止”。这修改任务结束策略，不代表新一次运动已执行。以下改动仅在电脑验证目录，未部署真机，不覆盖validated_goal_v1等成功快照。

正常结束条件：停稳后位置进入原有0.15m容差；目标有朝向时还须满足原有朝向容差。刹停/等待步态结束是动作内部阶段，不是提前宣告任务完成。最终还会用地图坐标重新核对到点结果。

## 总时长

- 原30秒为本轮短路线调试上限，不是厂商接口要求。rviz_goal_20261121_04实际因该上限结束，原失败结果保持不变。
- navigate.py和MotionPolicy默认duration=0：没有固定任务截止时间；正数仍表示显式选择的调试期限。独立看门狗仍检查控制循环0.20秒心跳，取消任务截止时间不取消故障停车。
- session.py不再另外用240秒结束任务，定位以duration=0运行，由监督器在任务结束、人工中断或异常退出时收尾。单独运行diagnostic_session.py仍默认180秒，显式0表示交给所属监督器管理。
- 等待RViz点击和定位初始化的时间限制仍存在。这两个等待发生在运动开始前，与“运动30秒后结束任务”不同。
- 定位/里程计失效、控制间断、地图净空、累计行走距离、动作次数、人工中断等原有检查保留。没有增加自动重试。

## 动作衔接缺陷

原前进阶段进入条件是距离大于到点容差0.15m，而退出条件又包含“距离小于停车补偿0.26m+0.05m”。这样剩余0.15～0.31m时可在一个控制周期后进入2秒等待。现在停车补偿只用于计算本次前进长度，不再对剩余距离重复应用。保留原有单段最短指令位移0.04m及转向偏移检查；0.05m近目标保护仍会触发刹停，而不是宣告到达。

原转向在误差大于容差时进入，在误差小于“容差+提前停车角”时退出，两者重叠会产生相同问题。现在每次转向的停止误差取min(原停止角带, 初始误差的一半)，保证新开始的小角度转向须有角度进展再进入等待。容差、速度和目标不变。

这两个修正消除逻辑上的单周期脉冲，不代表已标定真机短步态。常数停车补偿来自此前较长直行，不保证短距离修正和小角度转向同样准确；不能通过软件结果宣称物理到点。

通过tools/run_tests.sh运行本目录指定测试，共59项通过，日志为../evidence/completion_driven_tests_20261121.log。新增检查覆盖：超过30秒后正常到点、无任务期限时仍因输入失效/心跳间断停车、正数期限仍生效、近距离和近角度修正等待真实位姿进展，以及模拟监督器在300秒任务期间保持定位。测试没有注册运动源，监督器测试的进程和时钟均为替身。

rviz_goal_20261121_04结束后未自动再次运动。停止状态的现场确认仍待补充；下一次试验应先确认当前实际位置、朝向和净空，不能沿用已完成运动之前的静止起点。

另一个独立问题：rviz_live_20261121_01中传感器适配持续收到有效数据，但FAST-LIO点云和里程计输出间隔约8.9秒，定位因此失效。内部阻塞位置尚未确定；本次任务时间策略和动作衔接修改没有解决它。

## 继续验证时补充

取消整趟任务时限后，新增单次动作无进展判断：持续发出前进指令时5秒内没有累计向前0.03m，或转向指令下5秒内没有沿所选方向转过0.08rad，按no_motion_progress异常停车。计时随方向上的实际进展更新，动作正常推进不会因为总时长结束。动作达到本段刹停条件时优先进入等待，不要求已完成的小动作继续走满进展阈值。

5秒参考此前单段起步实走的5秒观察范围并给起步延迟留余量；位移/角度阈值是调试用进展量，不是测量精度或厂商保证。它用于避免新鲜但静止的里程计让程序持续发指令。软件测试覆盖静止、微幅往返晃动、长于30秒仍可完成的慢速运动等，更新后的62项指定检查通过，日志../evidence/completion_driven_tests_20261121_02.log。真机表现仍待本候选现场验证。
