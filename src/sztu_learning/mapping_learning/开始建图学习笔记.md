## 第1小步：z坐标不一定等于离地高度（已确认理解）

筛选高度之前，必须知道坐标系的向上方向，以及地面在该坐标系中的位置。
以下只是解释用的假设：z轴竖直向上，坐标原点在离地1米的传感器上。

- 地面在这个坐标系中的z是-1米。
- 一个点的z是-0.8米，表示它比传感器低0.8米。
- 它的离地高度是 `-0.8 - (-1.0) = 0.2` 米。

所以不能看到点的z就直接称为离地高度。
真实点云还可能整体倾斜，不能直接套用上述假设；后续逐步处理。
本步只确认概念，没有新增转换程序，也没有处理真实点云。

学习者正确回答：在上述假设下，z为-0.3米的点离地0.7米。

## 第2小步：计算高度之前，先确认向上方向（已确认理解）

第1步的计算有一个前提：z轴竖直向上。
真实点云所用坐标系的z轴不一定满足这个前提，不能仅凭轴的名字判断。
例如传感器倾斜安装时，它自身的z轴可能也是倾斜的。

后续要把点云转换到一个z轴竖直向上的坐标系，再处理地面的高度。
转换坐标系改变的是同一个点的坐标表示，不会让真实墙体或物体移动。
本步只讲目的，尚未引入旋转计算或新增代码。

学习者正确回答：转换坐标系不会让真实墙体移动。

## 第3小步：让地面的高度变成0（已完成基础确认）

本步假设z轴已经竖直向上，只处理地面不在z=0的问题，不执行真实点云的方向对齐。
示例程序：`step01_ground_height.py`，在电脑本地运行，不需要ROS或机器人。

`ground_z` 是地面原来的z坐标，`point_z_values` 是几个示例点原来的z坐标。
对每个点计算 `height = point_z - ground_z`，得到该点的离地高度。
三个示例的输出分别为0.0米、0.2米、0.7米。
打印格式 `.1f` 只控制显示为一位小数，不改变计算结果。

对所有点采用相同的高度平移后，地面变成0，点与地面的距离保持不变。
这些是解释用的假设数值，尚未读取或转换真实点云。

地面z=-1.2米、点z=-0.5米时，离地高度是0.7米；已补讲减去负数的计算。
学习者正确回答：点在地面上时，离地高度为0米。

## 第5小步：投影和栅格位置（已确认理解）

高度决定点是否参与地图，x、y决定其平面位置。同一竖直柱子不同高度的点可以投到同一个格子。
分辨率是格子边长，单位米/格；地图原点在本例中指覆盖区域的左下角。

```python
column = math.floor((point_x - origin_x) / resolution)
row = math.floor((point_y - origin_y) / resolution)
```

先减去边界坐标得到距离，再除以分辨率并向下取整。x对应列，y对应行。
学习者已正确回答组合例子：第2列、第1行。
后续不再检查简单算术或讲Python基础，重点讲地图概念和核心实现。

## 第6小步：占用、空闲与未知（已确认理解）

- 100表示占用，不表示点的数量；同一格重复命中不累加。
- 0表示空闲，需要观测证据，不能因为没有点就直接标记。
- -1表示未知。墙后未观测区域保留未知。

射线追踪需要对应观测时的雷达位置；射线终点之后不能继续标为空闲。
目前仅用合并点云标记障碍物，其他区域保留未知，尚不是完整的导航地图。
被高度筛掉的点不更新格子，不清除已有占用。
占用表示障碍物证据；是否能从旁边通过还取决于机器人尺寸及周边空间。

## 第10小步：灰度图片与上下方向（已确认理解）

地图状态100/0/-1分别转换为图片亮度0/254/205，即黑色占用、接近白色空闲、灰色未知。

## 第11小步：YAML解释地图（已确认基本字段）

image指定图片；resolution是米/格；origin为栅格左下角的[x,y,yaw]，不是机器人位姿。
negate=0时灰度对应的占用判断值为(255-像素亮度)/255。
大于occupied_thresh=0.65判为占用，小于free_thresh=0.196判为空闲，中间为未知。

## 2026-11-21 补充理解：Nav2选点限制与没有真机的软件测试

现在验证入口只接收“前方约0.6米、右侧约0.4米”附近的目标，黄色圆心周围0.20米以外会拒绝，并限制路线和累计行走2米。这是为当次短距离实走设置的入口限制，不是Nav2的能力上限。以后可以支持选择地图内其他可达位置；墙内、未知区域和机器人外形不能通过的位置仍不是有效目标。

电脑软件测试的循环：真实Nav2软件收到目标→输出速度→Plant程序按模型计算新的位置/朝向→通过ROS话题反馈给Nav2→Nav2再次计算速度。Plant相当于一个只有数字状态的简化机器人，不包含真实脚步、真实传感器或真实地图匹配。原地图会加载到Nav2供规划和静态碰撞预测使用，但模型没有完整的物理碰撞仿真。

例如模型位于x=0、朝向+x，假设实际前进速度恒为0.1m/s，经过1秒就更新到x=0.1。真实测试还用一阶响应模拟速度逐渐变化和停车尾随。公式只描述假设的模型，不代表真实机器人一定这样运动。

第一项软件任务给出新的XY和终点朝向；完成后，第二项使用相同目标XY、改变终点朝向，检查旋转和到点判定。两项都检查官方动作成功，并继续计算模型2.5秒，再比较模型最终状态与目标：位置差<=0.15m、朝向差<=0.10rad（约5.7°）。知道的是“模型内是否完成”，不是“真实机器人必然完成”。

原0.12秒角速度响应模型通过；随后把测试中的响应时间设为0.5秒作为压力场景，第二项出现官方动作成功但最终朝向差约13.74°，软件检查失败。说明先前通过只覆盖原模型条件，较长停止响应必须另外处理。0.5秒是压力场景参数，不是已经独立标定的真机参数。

本轮实走已打通RViz选点→Nav2→机器人转向/前进/停车；最新停止后定位估计位置差10.6厘米通过，但朝向差19.5°未通过。当前继续核对停止响应，不能把软件测试通过当作真机导航精度验收。
