写/改任何一个 rclpy 节点时对照用。配套 第 1 课。

最小模板

import rclpy
from rclpy.node import Node

class MyNode(Node):
    def __init__(self):
        super().__init__('my_node')      # 唯一名字
        # 在这里声明接口 ↓

def main(args=None):
    rclpy.init(args=args)
    node = MyNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()

四种接口声明（写在 __init__ 里）

要做的事声明拿到什么
发消息self.create_publisher(Msg, 'topic', qos)publisher，用 .publish(msg)
收消息self.create_subscription(Msg, 'topic', cb, qos)每来一条消息调 cb(msg)
调服务self.create_client(Srv, 'srv')client，用 .call_async(req)
定时干活self.create_timer(period_sec, cb)每隔 period 调一次 cb()

心智模型

一句话 __init__ 声明（一次），回调/方法里使用（反复），spin 之后节点才真正响应事件。

常用动作对照

你想…去哪写
加一个新能力类里加一个方法
让节点响应新消息create_subscription + 一个回调方法
让节点周期性执行create_timer + 一个回调方法
让 ros2 run 能启动它setup.py 的 entry_points，然后 colcon build
看节点在不在线ros2 node list（看到的是 super().__init__ 里的名字）

易踩的坑

症状多半原因
节点起不来 / 名字冲突同名节点已在运行（如 bridge 已内含该控制器）
改了代码没生效忘了重新 colcon build + source install/setup
ros2 run 找不到命令entry_points 没写对或没重建
回调从不触发没进 spin，或 topic 名 / QoS 不匹配
