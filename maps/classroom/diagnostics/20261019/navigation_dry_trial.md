# 导航空跑、指令路径与覆盖检查

在候选图保持加载、FAST-LIO/AMCL 不重启、`live=false` 且三个覆盖标志均为
false 的状态下，完成一次 `NavigateToPose` 软件链路验证。目标是当时导航
TF 前方 0.6 m，接受后运行约 6 s，主动取消得到返回码 0、一个取消中的目标，
最终 action 状态 5（CANCELED）。这是有意取消的空跑，**不是到点成功或实走**。

| 观测话题 | 消息数 | 非零消息数 |
| --- | ---: | ---: |
| `/cmd_vel_nav_raw` | 61 | 60 |
| `/cmd_vel_nav` | 140 | 139 |
| `/cmd_vel` | 443 | 0 |
| `/aima/mc/locomotion/velocity` | 452 | 0 |

控制器及平滑器确实输出了非零速度，观测分量最大绝对值 0.25；取消后两者
最后消息均为零。安全门输出始终为零。没有创建硬件发布者、注册运控输入源、
改变 MC 配置、重设初始位姿或更改地图；前、紧邻发目标前、后均实读四个标志
为 false。本次证明静态控制链路及取消流程可运行，不能证明硬件停止响应。

## 速度消息实际去向

此前 25 s 只读采样中，`/cmd_vel` 有本项目安全门和
`controller_server_ros_node` 两个发布端，但发现的订阅端只有此次观察器；
`/cmd_vel_nav_raw` 的执行链路通向本项目平滑器，`/cmd_vel_nav` 通向安全门。
因此不能凭两个 `/cmd_vel` 发布者推断它们在争抢本项目的执行输入。发现
快照不保证未来不会出现新订阅者，实走前仍需按当前图复核。

真正的 AimDK 运控话题发现 `mc_ros2_node3341` 等订阅者。25 s 收到 1092 条
该话题消息，source 均为 `rc`、速度均零；空跑期间再收到 452 条 rc 零速。
已发现其他 SDK 发布端，但本次 VOLATILE 观察不读取其历史，不能据此宣称
那些源永远不发命令。

只读 `GetCurrentInputSource` 返回 code=0，选中 `rc`、priority=80、
timeout=1000 ms，响应年龄约 6.16 ms。此时自研源尚未启用，因而**不能据此
断言 rc 会阻止已激活的自研源、已验证交接或必须操作某个 SDK 开关**。
官方 AimDK 1.0.0 的 MC 控制信号文档规定按有效源优先级及超时仲裁；
遥控器连接说明只介绍配对，没有给出 SDK 释放按键。不指导试按未知组合，
不禁用 rc、不提高导航优先级以掩盖交接问题。用户反馈不知道是否有此开关。

原始观察器尝试保存 MessageInfo 中的 publisher_gid，但安装版本未提供该键，
逐消息 GID 均为空；端点 GID 只作图清单，**未完成逐写端流量归属证明**。

## 五扇区检查的实际含义

25 s 内收到 222 帧安全扫描，有限回波的总角度范围约 −46.314° 至 +44.312°，
222 帧全部占满前方五个宽扇区。约 90°的回波仍能落入全部五个扇区，说明
它只是一项回波存活检查，不能单独证明 120°连续视野或脚边净空。

复用已有椅子/移走对照原始点云，无需重新摆椅：修正后的正前椅子帧最近安全
回波约 0.932 m，移走帧约 2.508 m；该移走帧原始点角度约 −53.62° 至
+52.31°，高度过滤后的安全回波约 −46.27° 至 +43.94°。这些是已观测物体
表面的方向和距离，**不是实际视场边界、最近可测距或无人区域证明**。
没有根据此数据把覆盖要求从 120°降为 90°，也没有删除稀疏点或把 NaN 当空闲。
代码注释及运行手册已明确：圆形足迹旋转不扩张只是模型性质，不证明人形
机器人脚/身体扫掠范围得到实时覆盖。

## 代价地图配置核实与更正

曾只看基础 YAML，误判代价地图仍使用定位扫描；此判断撤回。启动文件会
覆盖该设置，且实际全局、局部代价地图参数均实读到：

- `obstacle_layer.scan.topic=/sztu/safety_scan`
- `expected_update_rate=0.5`、`observation_persistence=0.0`
- `inf_is_valid=false`、`obstacle_layer.enabled=true`

AMCL 保持 `/sztu/scan`。局部代价地图第一次查询超时，单独重试后获得上述
响应；保留两次原始结果。未修改运行配置或重启服务。

图清单发现头部 RGBD 深度图及标定信息发布端，随后另做约 10 s 的只读采集。
收到 184 帧 1280×720、16UC1 深度图和对应内参，frame 为
`rgbd_depth_head_front`；173 帧取得图像精确时刻到 `base_link` 的 TF。
最后一帧 921600 像素中有 815240 个正有限原始深度值；原始单位及相机坐标轴
语义尚未独立核实，不直接按毫米反投影接入安全门。

接收年龄中位约 0.054 s、最大约 0.880 s，20 帧超过 0.5 s；保存了启动时
TF 尚未发现/未来外推失败。未进行重试补齐或把这些帧计为有效几何输入。
仅证明此窗口存在可进一步评估的深度流及大部分精确时刻 TF，不能证明其
能补足脚边、侧后方盲区。深度与雷达融合仍未实现或启用。

保持 `live=false`、三个覆盖标志 false，停车余量仍为 0.25 m，`sztu-bridge`
不启动；候选地图仍只作静态诊断。当前需解决的是实际可见区域与步态扫掠的
