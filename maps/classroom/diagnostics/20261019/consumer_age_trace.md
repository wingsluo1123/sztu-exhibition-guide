# 实测超时帧与消费者年龄校验

本轮只运行独立候选和只读观测，不重启 LIO、不切换主导航、不发导航目标。
操作者此前确认已移除椅子；此次没有重新索取现场确认，因此场地状态只沿用
此前描述，不能作为新的独立空场真值。`live` 和三个覆盖标志实读均为 false，
40 秒内观测到 1846 条速度命令，全部为零。

## 捕获到的同一帧

[逐帧摘要](candidate_matched_timing_summary.json) 对应修正发布顺序之前的
adapter（`d2ca68f` 的运行代码）。候选增加内存追踪，观测端沿用现场旧 Humble
的 SingleThreadedExecutor 取消息路径并保留 DDS 元数据，同时订阅点云、
原/候选扫描和状态，复现先前观测负载。追踪增加开销，不能宣称与无追踪时
完全等价。真实图发现 `/lio/points` 只有 `cloud_to_velodyne` 一个发布者。

捕获点云时间戳 `1792412659816094000 ns`，下表时间均相对此时间戳：

| 阶段 | 年龄 / 耗时 |
|---|---|
| 候选收到点云 | 年龄 0.161071 秒 |
| 从接收到成功处理开始 | 等待 0.212234 秒 |
| 成功处理中的地面拟合 | 耗时 0.010730 秒 |
| 处理完成时的发布检查 | 年龄 0.412648 秒 |
| 安全扫描 DDS 写入时间 | 年龄 0.412983 秒 |
| DDS 写入至观测端 RMW 接收 | 耗时 0.121105 秒 |
| RMW 接收至观测回调 | 耗时 0.000716 秒 |
| 观测回调实际收到扫描 | 年龄 **0.534804 秒** |

首次失败等待的是精确导航 TF；后续一段时间最新 TF 比点云时刻仅早
0.138 毫秒，但还必须等到后一个里程计样本才能插值，不使用不同时间的
姿态替代。成功时实际查到同刻骨盆和两脚踝变换。安全 publish 调用耗时
6.657 毫秒，小于之后的交付间隔。旧扫描同一时间戳也在 0.541696 秒
到达，且其 DDS 交付间隔约 120 毫秒。

这说明本例由 TF 等待与消息交付长尾叠加，不能归因为“地面拟合太慢”。
DDS 内部调度、传输及主机调度的具体来源尚未分离；本例不解释全部历史失败。
5 秒之后本窗口未再超时，但此前另一次移除椅子的窗口在 6.388 秒仍曾超时，
不能因此撤销那个失败。

## 发布端加固与接收端回归

安全扫描改为先于定位扫描发送，避免定位写入阻塞安全消息。保留处理后的
总年龄检查，并在**每次** publish 之前重新检查原点云年龄与单调时钟经过
时间；第一条发送期间若第二条超时或时钟向后跳，就消费该帧并停止发送第二条。
`scans_published` 继续表示完整扫描对，新增两个分输出计数显示部分发布。
不改变时间戳、过滤高度、同刻 TF 要求或现有 0.5 秒限制。

这项加固覆盖发布调用之间的检查空隙；**它不消除已经写入 DDS 后的交付延迟**。
安全门原有的接收年龄校验仍是必要条件。用上述同一真实时间戳构造两项回归：
在 DDS 写入时刻该消息可被接受；在实际接收时刻必须被拒绝，并且即使刚收到
新的前进命令，门输出也为零。该回归验证软件逻辑，不代表实物停车测量。

`ROS_DOMAIN_ID=42 ROS_LOCALHOST_ONLY=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
tools/run_tests.sh` 定向运行 ground/queue/TF/projection/safety 五个测试文件：
**95 passed in 0.35s**。新增场景覆盖安全优先、第一条 publish 阻塞期间的
墙钟前进/后退与单调时间过期，以及上述真实 DDS 延迟的接收判定。
这是单元逻辑检查，不把测试替身结果当作真机硬件停止证明。

## 地图为何不能替代这些检查

地图的空闲格表示建图时被观测为空闲，未知格没有无障碍保证。已走过的线
也不代表当前整个人形机器人和步态扫过的区域仍然净空。椅子、人或低矮物品
可以后来进入已知路线，必须由实时感知更新；旧过滤已实际遗漏低处回波。
当前全局规划 `track_unknown_space=true`、`allow_unknown=false`，保持未知
区域不可直接穿行；不通过把未知涂为空闲来使测试通过。

后续真机只复核本次发布加固与接收检查，不重复已完成的摆椅流程。零星原始
回波仍保留，物理来源尚未确认；视野覆盖和实物停止行为也未因此得到证明。
