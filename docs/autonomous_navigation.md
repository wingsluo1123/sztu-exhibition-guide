# 自主导航启动

当前导航使用自研 FAST-LIO + Nav2 + AMCL；厂商 SLAM 不参与。

## 启动顺序

1. 停掉会抢速度的旧服务：

   ```bash
   systemctl --user stop sztu-bridge
   ```

2. 终端一启动实时里程计和点云（保持运行）：

   ```bash
   cd ~/sztu
   source /opt/ros/humble/setup.bash
   source install/setup.bash
   tools/run_lio_live.sh --bridge --map-frame maps/testroom.yaml
   ```

3. 终端二启动已知地图导航（默认 `live:=false`，不会发硬件指令）：

   ```bash
   cd ~/sztu
   source /opt/ros/humble/setup.bash
   source install/setup.bash
   ros2 launch sztu_navigation autonomous.launch.py \
     map:=/home/agi/sztu/maps/testroom.yaml \
     live:=false
   ```

4. 在 RViz 设置一次 `/initialpose`，必须是机器人当前在 `testroom` 地图中的真实位置和朝向。等 `/amcl_pose` 协方差稳定后再发导航目标或启动讲解点位。

   保持机器人静止，用工具栏的 `2D Pose Estimate` 在实际位置按下鼠标，沿机器人朝向拖出箭头后松开。设置一次后观察，不要连续重复设置。定位正确还需确认雷达点与地图墙面重合；低协方差本身不能证明位置正确。重启 FAST-LIO 或 AMCL 后需要重新设置。

   只重启 RViz 不需要重设初始位置。`AMCL Pose` 显示使用 `Reliable` / `Transient Local`，可获取 AMCL 保留的最后一条位姿；箭头显示出来不代表该位姿仍然新鲜，仍须确认实时雷达点和定位持续更新。

## 定位抖动修复与当前限制

AMCL 使用 `OmniMotionModel`。腿式机器人静止时的横向里程计抖动，可能让差速模型将微小平移解释为大幅转向；全向模型按实际偏航变化计算旋转噪声。初始位姿转接在机器人上使用本机时钟，保留 RViz 提供的位置、朝向和协方差；它用于静止时手动设置当前位置，不用于转发带历史运动含义的位姿。传感器的测量时间戳保持原样。

扫描适配器使用最多 8 帧的等待队列，允许对应 TF 稍晚到达。等待和接收前的延迟共同计入原有 0.5 秒寿命；超时仍丢弃。最新 TF 的回退时间差上限仍为 0.15 秒，机器人断流时仍不能输出有效扫描。此前“重复旋转造成抖动”的判断已撤回；扫描仍需要按机身滚转、俯仰水平化。

旧运行链路实测 FAST-LIO 原始里程计中位延迟约 0.48 秒，原始雷达点云约 0.12 秒；开发机与机器人时钟相差约 0.93 秒。这些证据提示计算或传输延迟与跨机时间问题，尚不能断定注册点云发布是积压的唯一原因。实时导航模式关闭 `/cloud_registered` 发布，`--map` 建图模式保留该输出；静止复测时原始里程计中位延迟约 0.08 秒，扫描恢复输出。地图及点位没有重生成。

2026-10-09 真机静止复测使用 `20261009_194733_live` 运行链路，保持 `live=false`。操作者确认仍在上次初始位置和朝向后，只设置一次初始位姿 `(1.943, 0.200, 0.030)`，等待 AMCL 收敛。随后 60 秒观察得到 99 条 AMCL 位姿；最后 30 秒 x/y 峰峰值分别为 0.009/0.015 m，航向峰峰值 0.178°，最终 x/y/航向方差为 0.000451/0.000354 m²、0.000143 rad²。Nav2 管理节点全部激活，观测到的 `/cmd_vel` 始终为零。

该次末帧 172 条有效雷达射线，在收敛位姿下到地图占据格的距离中位数为 0、p90 为 0.111 m，93.6% 小于等于 0.15 m；初始位姿对应的中位数为 0.05 m、p90 为 0.158 m。这个比较验证局部扫描与地图的匹配改善，不能替代独立位置测量。观测到的导航里程计/扫描中位年龄为 0.088/0.169 秒，但最大值仍为 0.519/0.714 秒；超出原有 0.5 秒预算的数据仍由安全门拦截，连续实走时效尚未验收。

同日约 20:26 的后续观察发现，原始点云接收年龄均值约 0.176 秒，但 FAST-LIO 里程计均值约 0.924 秒、最小约 0.544 秒；10 秒内没有新的 `/sztu/nav_odom` 或导航 TF，AMCL 更新中断。这说明早先的静止收敛结果不能证明长时间运行稳定；须解决里程计链路延迟并复测，保持 `live=false`，不放宽 0.5 秒数据寿命。

实时脚本现在设置 FAST-LIO `common.max_input_age_sec:=0.3`，按机器人时钟丢弃开始处理前已经过期的点云，给后续计算和传输预留 0.2 秒；不修改测量时间戳，也不删除两次雷达更新之间的 IMU 积分数据。默认值 0 表示关闭该策略，离线回放仍处理完整数据。补丁保存在 `tools/patches/fastlio_realtime.patch` 和 `fastlio_scan_backlog.h`，更新后运行 `tools/setup_fastlio.sh` 重新编译。时间倒退时点云与时间队列一起清空。扫描适配器在投影完成后再次检查寿命，过期则两种扫描都不发布。0.3 秒是初始处理预算，不能保证超负荷时每帧输出都新鲜；下游原有 0.5 秒门槛保持不变。

点云 XYZ 读取改为按真实 `point_step` 步长批量解析，保留原有非有限点过滤。真机同一帧五次测量中位耗时：原逐点读取约 647 ms，批量读取约 1.5 ms；这个测量包含高系统负载下的调度时间，不是纯 CPU 耗时。补丁和批量读取部署后，约 21:07 的 60 秒静止观察收到 100 条 AMCL 位姿；最后 30 秒 x/y 峰峰值 0.009/0.023 m、航向峰峰值 0.408°，最终位姿 `(1.712, -0.061, 0.088)`，x/y/航向方差为 0.000398/0.003376 m²、0.000277 rad²。原始里程计、导航里程计、扫描和 AMCL 接收年龄中位数分别为 0.075/0.093/0.144/0.217 秒，`/cmd_vel` 未观测到非零指令。仍有超过 0.5 秒的传输尖峰，连续运动时效、真实位置和扫描匹配仍须验收；这些静止结果不构成实走放行。

## 路径规划和障碍物显示验证（2026-10-09）

保持机器人静止和 `live=false`，本次只调用 `ComputePathToPose`，未发送导航执行动作；规划观察期间未收到非零 `/cmd_vel`。参数服务确认两张代价地图均启用障碍层，实际输入为 `/sztu/safety_scan`，规划半径均为 0.85 m。

- 当前估计位置约 `(1.773, -0.001)`，静态地图最近占据格距其中心约 0.62 m，起点代价格为 99（原始值 253，位于内切膨胀区）。从实际起点到两个附近目标的规划均失败。须现场核对附近墙体、家具和地图定位，不能因此缩小规划半径或直接删除地图障碍。
- 使用显式假设空旷起点 `(1.171, 0.100)`，到三个目标的真机规划均成功，路径长约 1.88、2.12、2.34 m。机器人没有移动到该起点；这些路线不能作为当前机器人位置的执行路线。以 1.25 cm 间距在当时全局代价地图快照上采样，未进入未知格或内切膨胀区；距占据格中心的最小距离约 0.885 m，仅代表该快照下的规划结果。
- 同一假设起点到地图障碍内部目标的规划失败，验证拒绝不可达目标。三个成功规划仅证明该地图上的规划功能，不能证明真实运动避障。
- 同步比较五组原始局部代价地图与原时间戳 TF 对应的安全扫描：每组有 100–102 个落点位于局部地图范围内，99%–100% 距障碍格不超过 0.15 m，中位距离均为 0，p90 为 0–0.05 m。初次异步快照比对出现偏差，改用原始代价地图服务和对应扫描时刻后得到以上结果。

RViz 默认显示 `Local Obstacles`（局部障碍及膨胀区域）、`Planning Footprint`（浅蓝色规划轮廓）、`Safety Scan`（橙色安全扫描），原 `Localization Scan` 为红色定位扫描；`Global Costmap` 可勾选查看全局规划禁行区域。绿色 `Planned Path` 是规划输出，出现路径本身不表示机器人已执行或允许执行。当前实际起点规划失败，因此可能看不到有效绿色路线。

真实人员进入、离开后的障碍标记和清除，以及运动中的停车和绕行仍待现场测试；静态显示与合成仿真不能替代这些验收。

## 真机放行条件

胸前 E1R 只有约 120° 水平视场；在没有确认侧后方传感器前，不要把 `live` 改为 `true`。安全门默认要求新鲜点云、里程计、AMCL 位姿和 `map → sztu_nav_base` TF，任一失效就输出零速度。

完成实测并确认传感器覆盖整个机器人扫掠范围后，才可由现场人员执行：

```bash
ros2 launch sztu_navigation autonomous.launch.py \
  map:=/home/agi/sztu/maps/testroom.yaml \
  live:=true surround_coverage_verified:=true
```

仍需现场人员在急停旁边先做静止、低速、单点和动态障碍测试。`Spin`、`BackUp` 恢复动作没有启用；遇到人或传感器断流会等待并重新规划。

## 验证

开发机仿真（隔离域 `42`）已验证：地图定位、动态障碍绕行、障碍移开后重新规划、传感器断流停车和 Nav2 action 取消。测试命令：

```bash
ROS_DOMAIN_ID=42 tools/run_tests.sh
ROS_DOMAIN_ID=42 python3 tools/test_nav2_runtime.py
```

2026-10-09 软件测试：726 通过、2 跳过。最新仿真包含初始位姿转接、TF 等待队列、批量点云读取和投影后寿命复查；静止时加入 2 cm 里程计抖动、250 ms TF 延迟，定位最大位置误差 0.044 m。恢复正常 TF 后，到点误差 0.274 m，绕行横向偏移 1.546 m，距测试障碍最小中心净空 1.181 m；阻断路线等待、障碍移除后重新规划、传感器断流期间拒绝新鲜速度指令均通过。这些结果仅来自合成地图、合成全向点云和理想速度响应。单元测试还覆盖 FAST-LIO 积压丢弃时队列配对、原始时间戳保留、离线模式禁用和边界时刻保留。单元测试和运行时仿真必须依次执行，同在域 42 并行运行会产生重复 action server 等串扰。

速度上限 0.25 m/s、0.7 rad/s。规划半径 0.85 m 包含保守裕量；真实机器人半径 0.40 m、额外裕量 0.15 m、滑行预留 0.25 m 仍需现场测量。AMCL 的位置方差上限 0.09 m²、航向方差上限 0.07 rad² 是初始门槛，低协方差不能单独证明定位正确，必须核对地图中的墙和机器人真实位置。

真机已安装 Nav2 1.1.18 并编译导航和讲解包，`live=false` 静止定位、局部扫描与地图匹配和 Nav2 激活已验证；开发机 Nav2 为 1.1.20。真机未做自主运动、制动距离和侧后方覆盖验证。完整的人流环境自主导航尚未验收。
