# 当前X2运控状态契约与下一步

## 根因与依据

2026-10-20查阅机器人随附AimDK_X2 1.1.0文档的
`dev/Interface/control_mod/mc_status.html`和`modeswitch.html`：

| 字段 | 当前文档 | 旧生成IDL |
|---|---|---|
| FSM 4 | STABLE 稳定 | SAFE |
| FSM 5 | MOVING 运动中 | SPECIAL |
| FSM 6 | SAFE 安全 | TEST |
| FSM 7、8 | SPECIAL、TEST | 未包含 |
| current_action | 保留；v0.8.2起不使用 | 仍列出旧动作数值 |
| status 200 | TRANSITION 切换中 | TRANSITION |

模式说明同时明确v0.8.0+稳定站立与走跑一体化、随控制情况自动切换。
这与本次实机STAND/TRANSITION→LOCOMOTION/MOVING→STAND轨迹相符。
先前依据旧IDL拒绝FSM5的结论撤回；旧试验和时序失败均保留。

两页HTML和正文归档于两机
`~/.local/state/sztu-nav-diagnosis/20261020_mc_contract/`；哈希见
[契约摘要](../maps/classroom/diagnostics/20261020/mc_contract_summary.json)。
没有使用厂商授权外的SLAM/导航功能，也不更改系统消息定义。

## 修正规则

首次起步只允许新鲜的STAND_DEFAULT、status=100、FSM=4、body=1。
已起步后，描述仅限STAND_DEFAULT/LOCOMOTION_DEFAULT，FSM仅限4/5，
body必须为1；status=100正常，status=200只作为有限切换。旧动作枚举0
不单独证明任何模式，明确阻尼描述/枚举仍优先停止。

连续TRANSITION最长2秒，按单调时钟计时，新的切换消息不会续期。
这是自研调试超时：参考此前零速后约1.50秒的切换记录，再加0.5秒消息
年龄预算；不是厂家保证值或物理停车时间。它必须在新数据上确认，旧失败
不会因此改判通过。单次非零脉冲上限仍1秒，不延长以等待状态切换。

消息年龄0.5秒与速度回读0.25秒限制保持。阻尼、SAFE、未知/启动/结束/
SPECIAL/TEST状态、非站立姿态、不可中断切换status=300或超时均停止；
已起步时锁停。健康消息、恢复站立和新旧导航速度均不能清除故障历史。
正常RUNNING可结束尚未超时的合法切换窗口，不是故障后的自动恢复。

## 验证与现场顺序

先在domain42隔离域验证正常自动切换、切换超时、消息失联、阻尼优先、
未知状态拒绝和禁止旧命令重放；真实轨迹离线回归使用连续样本，但其ROS
回调时间未保存，源年龄采用模拟值，不声称恢复原始时延。

软件通过后保持live=false、不重启定位：先由操作者在保护下有意恢复
站立，再只读核对控制源、状态与定位。随后如获新的一次试验授权，由操作者
执行0.10m/s、最多1秒的受保护脉冲，在步态期间触发阻尼。上次单次授权
已消耗，本修正不授权重跑`01`入口。没有按键沿，仍不能量化抢停延时。

通过受保护测试后，才安排带银行卡长度参照的地面停车测量，再评估身体
扫掠/近身观测与地图条件，进入受监督的短程Nav2实走。深度诊断候选流
当前不满足连续安全覆盖，三个覆盖标志继续false。
