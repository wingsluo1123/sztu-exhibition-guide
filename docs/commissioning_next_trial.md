## 软件与恢复规则

`McStateGuard`以0.5s源年龄和单调时间监督状态。阻尼描述、动作枚举3、
fsm6、body_status5任一出现就锁停。后两项是既有保守排除条件，SDK枚举实际
称TEST和SQUAT，不能称为独立的阻尼枚举；本次保留其停止行为及旧原因码。
字段未同步时停止优先；丢失/无效状态
在起步前禁止发非零，在起步后锁停。回调长时间停顿后收到新鲜状态也不能
掩盖中间缺口。后来站立消息、非零Nav2命令均不能清除停止历史。

站立组合依据本次真机记录：STAND_DEFAULT、动作枚举0、fsm4、body_status1、
动作状态100。兼容枚举200与fsm2，以及LOCOMOTION_DEFAULT/0或300/fsm2、3、4，
属于接口调试允许集，尚无本项目实物步态状态轨迹确认；未知组合导致本次
测试中止，不能为了完成试验临时放宽。缺少McCommonState的旧SDK拒绝带
状态监督的执行，且不注册运控源。

停止后先取消旧导航目标、确认机器人和控制源及定位状态，再决定是否有意
重启相关控制进程；需要新目标，不能借恢复站立续跑旧目标。诊断试验不自动
重启、复位、恢复站立或提高SDK优先级。默认导航继续live=false，覆盖标志
均false，停车余量继续0.25m。用户建议20cm是待实测参考，不直接替换余量。

## 已执行试验的包络与入口（历史记录，不可重跑）

问题：在SDK产生前进步态期间，操作者触发已验证的阻尼组合后，实物能否
进入阻尼，软件能否锁定零速且不恢复起步？一次尝试，无自动重试。

条件：现场固定防跌支撑、操作者在旁且能使用L2+R2+创建键；机器人静止
站立，现有导航保持只规划、sztu-bridge停止。仅限受保护条件，不能把本文
命令用于无保护地面导航。上一次前进/静止阻尼的单次授权已经执行完毕。

包络：SDK优先级45（低于rc80），正向0.10m/s、非零最多1s，倒计时5s
只发零速；随后至少3s零速并有独立清理阶段。不转向、不侧移、不倒退。
一旦出现步态，在这一秒内由操作者按一次阻尼组合。没赶上非零窗口时，
这次记录不能算运动中接管验证，不自行再试，也不自动恢复站立。

预览不连接ROS或注册输入源，在机器人终端执行：

```bash
cd ~/sztu
bash tools/run_restrained_handoff.sh --preview /tmp/sztu_handoff_preview_new
```

现场确认这一次包络后，操作者执行以下单次入口。输出名前缀必须未用过；
持久锁目录拒绝重跑同一入口，日志完整保存DDS信息，终端只留关键提示：

```bash
cd ~/sztu
bash tools/run_restrained_handoff.sh --execute /tmp/sztu_handoff_guarded_20261020_01
```

等待 `PULSE_COUNTDOWN`；看到 `PULSE_STARTED` 并观察到步态时按一次
L2+R2+创建键。`PULSE_ENDED`只表示程序进入零速段，不等于实物已停。
状态/话题异常时工具只发零并退出；不要继续按键或重跑。异常动作立即按
熟悉的独立停止操作。SSH/进程失败无法保证程序清理，保护与接管须始终在旁。

判读：必须同时有现场在步态期间按键的报告、原始阻尼状态、随后无再次非零
的回读记录；命令话题本身不证明执行或物理停止。不把阻尼引起的身体下沉
算停车距离，没有按键时间沿就不报告响应延时。报告保持
`hardware_stop_verified=false`，人工观察另存。

## 银行卡距离参照（后续地面试验）

标准卡长边85.6mm，两次171.2mm，三次256.8mm。可在行走路径侧面用其
转移距离作标记，摆完移走卡和松动物，避免踩卡；不需拍卡面、卡号。
这能提供粗略独立长度参照，目视读数还受视差和反应时间影响。
需要区分整次前移距离和停止触发后的继续前移距离，后者才是停车距离。
仅看见“马上停”或里程计归零不算20cm已测通过。本轮受保护阻尼试验不
测试地面停车距离，也不因此直接开放自主导航。

后续进入地面短程试验前，只补齐与该包络有关的证据：实际脚/身体扫掠、
目标路径近身障碍观测、可用独立接管，以及明确有效的地图/目标位置。
相机画面外的缺口不能靠调整软件覆盖标志消除。
