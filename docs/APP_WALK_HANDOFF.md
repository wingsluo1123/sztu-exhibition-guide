# APP 走路功能适配提示词

请在 HarmonyOS `Robot_APP` 中适配机器人走路功能。机器人服务端已经依据 AimDK v1.0.0 官方接口完成：使用 `McLocomotionVelocity`、注册自定义输入源 `sdk_sztu_app`、50 Hz 发布并带 250 ms 失联自动停车。APP 只负责通过现有 TCP/WebSocket 连接发送文本命令，不实现 ROS 逻辑。

## 协议

- TCP 默认连接机器人 IP 的 `8888` 端口；每条文本以 `\r\n` 结尾。
- 进入走跑模式：发送 `WALK`（也兼容 `RUN`、`走跑模式`）。
- 服务端会自动执行安全序列：位控站立 → 稳定站立 → 走跑模式。
- 必须收到 `OK:WALK` 后才能启用摇杆；失败返回 `ERR:WALK`。
- 查询模式：发送 `MODE`，成功回复 `OK:MODE:<模式名>:<状态>`；目标模式为 `LOCOMOTION_DEFAULT`。
- 摇杆速度：持续发送 `JOY:<x>,<y>`，其中 x/y 范围均为 -100..100：
  - `y > 0` 前进，`y < 0` 后退；
  - `x > 0` 右转，`x < 0` 左转；
  - 当前不提供侧移。
- 停止：发送 `STOP`，回复 `OK:STOP`。
- 正常 `JOY` 不返回 ACK，避免高频消息刷屏；格式错误会返回 `ERR:JOY:bad_payload`。

## UI 与发送要求

1. 新增“进入走跑模式”按钮，点击后发送 `WALK`，等待回复期间按钮置灰并显示 loading，禁止重复发送。
2. 只有收到 `OK:WALK` 后才启用摇杆；收到 `ERR:WALK` 时保持禁用并提示用户检查机器人是否双脚落地、姿态是否安全。
3. 摇杆按住时以 20–50 Hz 持续发送 `JOY:x,y`；不要只在触摸开始时发送一帧。
4. 摇杆释放、页面失焦、应用进入后台、连接断开、组件销毁时，都必须立即发送一次 `STOP`。
5. 建议加 5–10% 死区：死区内发送 `JOY:0,0` 或 `STOP`，避免摇杆噪声导致机器人缓慢移动。
6. APP 端限制 x/y 到 [-100,100]，不要发送 NaN、Infinity 或附加单位。
7. 显示最近模式与连接状态；连接恢复后不要自动恢复旧速度，必须保持停止并要求用户重新操作摇杆。
8. `STOP` 是移动停止命令，不是硬件急停；真正异常时仍应使用遥控器/实体安全措施。

## 建议状态机

```text
DISCONNECTED
  -> CONNECTED_STANDBY
  -> (发送 WALK) ENTERING_LOCOMOTION
  -> (收到 OK:WALK) LOCOMOTION_READY
  -> (摇杆持续 JOY) MOVING
  -> (释放/失焦/断开) 发送 STOP -> LOCOMOTION_READY 或 DISCONNECTED
```

## 验收步骤

1. APP 连接 8888，发送 `MODE` 并正确展示回复。
2. 机器人放在平地、双脚完全触地，发送 `WALK`；等待收到 `OK:WALK`。
3. 前推摇杆，连续发送例如 `JOY:0,40`，机器人低速前进。
4. 右推摇杆，连续发送例如 `JOY:40,0`，机器人右转。
5. 松手后 250 ms 内机器人停止；同时确认 APP 主动发送了 `STOP`。
6. 强制断开网络，确认服务端看门狗自动清零，不继续保持旧速度。
7. `MODE` 查询结果应为 `LOCOMOTION_DEFAULT`（无指令约 2 秒后 AimDK 可能自动回到稳定站立，属官方机制）。

## 安全约束

首次实机测试请使用低幅值（例如 y=20–30），保持机器人周围无障碍并安排人员持遥控器。禁止在机器人吊起、零力矩、阻尼、未双脚落地或人员近距离围绕时启用摇杆。
